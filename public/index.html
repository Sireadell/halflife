A certification that expires

Halflife remembers every agent it has certified. When it checks one again it says what changed, and if the agent got worse it revokes the certificate it issued.

Why a certificate that never expires is worthless

An AI agent is not a bridge. It is a model, a prompt, a set of tools and a rate limit, and any of those can be changed in an afternoon by somebody who never thinks about the badge on the website. The agent that passed a resilience test in September quietly stops passing it in October, and the certificate goes on saying it passed, because nothing ever came along to change the word.

A badge issued once and never rechecked is not evidence about the agent. It is evidence that somebody ran a test once. Those are different claims, and only one of them is worth paying for.

What halflife actually does

It does not run the tests. It calls StressProof, a separate service that fires twelve fixed failure conditions at an agent's API, and pays for the run. What halflife adds is the part StressProof cannot do: remembering the last verdict, comparing it with this one, and deciding whether the certificate still holds.

Every agent is registered at a risk level, and the level decides two things and nothing else. There are no score thresholds anywhere: the bar is a verdict band, because agents legitimately vary between runs and any score cutoff would need an invented noise margin.

Risk levelRe-checkedMust holdFor example
LOWevery 30 daysPARTIALan assistant that answers questions and cannot spend anything
HIGHevery 7 daysRESILIENTan agent that moves money on behalf of somebody else
CRITICALevery dayRESILIENTan agent that trades on its own initiative

Five standings, and the differences between them are the product

A boolean would collapse all of this into "no certificate", which reads as an accusation in every case. Only one of the five is a finding about the agent.

StandingWhat happenedWhose failure
valid Checked recently enough, holding the band its risk level requires. nobody's
revoked It got worse. This agent held its band and no longer does. the agent's
never_qualified It never met the bar. Nothing valid was ever issued, so nothing has been taken away. nobody's, and it is not an accusation
stale Nobody checked. The last completed check is older than the risk level allows. halflife's
not_certified Halflife has never completed a check of this agent at all. nobody's

Revoked and never_qualified look identical from a single test result, and they are not the same statement. Revoking an agent that never qualified accuses it of getting worse when it did not change at all. So halflife remembers whether an agent has ever held the band at the risk level it is registered under now, and that memory is the only thing that can tell the two apart.

Stale is halflife's failure, not the agent's, and the wording, the stored record and the journal all keep it separate. It says halflife stopped knowing. An agent that was fine and has not been looked at since has done nothing wrong.

Staleness is recomputed against the clock on every single read, and never read back out of the stored record. If the word written at check time were the answer, a certificate written as valid on the first of the month would still read valid in March, because nobody re-checked, so nobody changed the word. That is the exact silent reassurance this product exists to remove.

The revocation is arguable rather than asserted. It is qualifiedForRiskLevel: "HIGH" that makes this a revocation instead of a never_qualified: this agent had held the bar before. And the fall is from one verdict band to another, not from one score to another, so an agent that merely drifted from 88 to 84 would still be valid.

Its history, as written

From GET /agents/:target/journal. The journal is append-only and never rewritten, so the history survives even though the standing record is overwritten on every run.

WhenWhat was written
2026-08-05 registered at HIGH risk. Must hold RESILIENT, re-checked every 7 days.
2026-08-05 certified RESILIENT, score 94, spec sp-1.4.0. First certification, nothing to compare with.
2026-08-12 certified RESILIENT, score 91, spec sp-1.4.0. Unchanged band, certificate stands.
2026-08-19 check could not be completed: StressProof unreachable. Certificate untouched, previous verdict left as it was. This is a gap in checking, not a finding about the agent.
2026-08-26 certified RESILIENT, score 89, spec sp-1.4.0. Unchanged band, certificate stands.
2026-09-02 certified PARTIAL, score 71, spec sp-1.4.0. Fell from RESILIENT to PARTIAL. Certificate revoked.

The 19 August line matters as much as the last one. A run halflife could not complete is never treated as a verdict about the agent: the remembered verdict is left exactly as it was, and the failure is recorded as a gap in checking. Halflife's own downtime cannot revoke anybody's certificate.

Using it

# register an agent at a risk level. This does not certify it.
curl -s -X POST /agents -H 'content-type: application/json' \
  -d '{"target":"https://your-agent.example/v1/ask","riskLevel":"HIGH"}'

# where it stands right now, judged against the clock now
curl -s /agents/https%3A%2F%2Fyour-agent.example%2Fv1%2Fask

# its history, exactly as written
curl -s /agents/https%3A%2F%2Fyour-agent.example%2Fv1%2Fask/journal

# whose certificate has run out of time
curl -s /due

Because a target is usually a URL, it is percent-encoded in the path. ?target= is accepted on the same routes for callers that would rather not encode anything.

What halflife will not tell you

  • It runs no probes of its own. Every verdict it reports came from StressProof. Halflife certifies nothing itself, it buys certification and remembers the result.
  • A certificate can only be as fresh as the last completed check. When halflife cannot check, it reports the certificate as stale rather than pretending it is current.
  • An agent with no registered re-check request can never be swept. It will go stale and stay stale until somebody asks for a check by hand.
  • It never compares results from two different versions of the test. A verdict that fell because the test changed is not an agent that got worse. Such a run is recorded as a fresh certification under the new version, flagged as one, and it does not hand back a certificate that was already revoked.
  • If memory is unreachable, every answer is a 503 saying so. Not a default, and not "no certificate on file". Halflife cannot honestly say nothing has changed about an agent it is unable to remember.
  • No payment has ever settled on Base, and halflife has never been registered on the live Virtuals ACP network. Both are written and tested against fakes. Neither is claimed as working, and no transaction hash is claimed here because none exists.
